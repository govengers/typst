# govengers/typst: design

Status: first version, 15.11.2026. Decisions are numbered (`T`); a later change gets a new number, never a rewrite.

`govengers/typst` renders PDF, SVG and PNG documents from Typst templates for govengers services. Profile `library`, Apache 2.0, Go 1.26; govengers/standards apply. The rule it serves: PDF generation always goes through Typst, rendered server-side by the typst CLI from the Go binary, with the server computing every value and the template only rendering it.

## 1. Decisions

| ID | Decision |
|----|----------|
| T1 | The library runs the `typst` CLI, one process per compile. Typst is a Rust program; a Go binding needs cgo or a WebAssembly build, both heavier to ship and slower than the static musl binary typst releases for every platform. A process also isolates a render: a runaway template is killed, its memory is gone with it. |
| T2 | `typst.New(&typst.Options{...})` resolves the binary to an absolute path once and runs `typst --version` (10 s bound). It fails when the binary is missing, below `MinimumVersion` (0.13.0, the oldest release with every flag `Compile` passes) or, when `Options.Version` is set, not exactly that version. A service pins the release it ships in its image in `Options.Version`, so a drifted binary fails at startup instead of rendering differently. |
| T3 | Every `Compile` creates a fresh directory under `Options.TemporaryDirectory` (`os.TempDir()` by default) with permissions for the owner only: `project/` holds `main.typ`, `data.json` and `Document.Files` and is the project root (`--root .`, the working directory); `packages/` and `cache/` sit outside the root. The directory is removed before `Compile` returns; a failed removal is returned as an error, because the directory holds the caller's data. |
| T4 | The data reaches the template only as the file `data.json` (`json("/data.json")`), encoded with `encoding/json`. Nothing of the document is on the command line: no `--input`, whose values are visible in the process list and bounded by the argument size limit. A template places data with `#data.field`, which typst treats as content, not markup, so user text needs no escaping on this path. |
| T5 | `Document.Files` are written by slash-separated relative paths. A path must satisfy `io/fs.ValidPath`, may not contain a backslash and may not be `main.typ` or `data.json` in any letter case (the directory can live on a case-insensitive file system). typst itself refuses any read outside the project root. |
| T6 | The process gets an empty environment except for the proxy variables (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, lower and upper case), which point to `127.0.0.1:0`. No `TYPST_*` variable of the service changes a render, and typst cannot download a package: an `#import "@preview/..."` resolves from `Options.PackagePath` (`--package-path`, laid out `<namespace>/<name>/<version>`) or fails with typst's "failed to download package". The package cache is a fresh empty directory per compile. Packages are vendored into the image, never fetched at render time. |
| T7 | System fonts are off by default (`--ignore-system-fonts`), so a render looks the same on a laptop and in a distroless image; `Options.SystemFonts` turns them on. `Options.FontPaths` must be existing directories, made absolute, and are passed joined by the OS list separator; a path containing the separator is refused. typst silently ignores a missing font directory, so the check at `New` turns a wrong font in production into a startup error. typst's embedded fonts stay available. |
| T8 | The output is read from stdout (`-`), never from a file, through a buffer capped at `Options.MaximumOutputSize` (64 MiB by default). A write beyond the cap cancels the run, which kills the process, and `Compile` returns `ErrOutputTooLarge`; the disk never holds more than the inputs. stderr is kept up to 64 KiB, the rest dropped. |
| T9 | A PDF holds every page; `Document.Page` must be zero for it. SVG and PNG are one image per page, and typst cannot write several images to stdout, so an image compile renders exactly one page: `Document.Page`, counted from 1, the first when zero (`--pages`). typst exits 0 without output for a page beyond the document, which `Compile` returns as `ErrPageNotFound`. `Document.PixelsPerInch` (`--ppi`) is valid for PNG only. HTML export is left out while typst marks it experimental. |
| T10 | `Options.Timeout` (30 s by default) bounds a compile; the process is killed through `exec.CommandContext`, `WaitDelay` bounds the wait for its pipes to 5 s. `Compile` tells the three ends apart by the context's cause: the caller's context ended (its error, wrapped), the timeout (`ErrTimeout`), the output cap (`ErrOutputTooLarge`). A run that finished before a cancellation arrived keeps its output. |
| T11 | Errors: `ErrInvalidDocument` before anything runs; `*CompileError{ExitCode, Diagnostics}` when typst refuses the template, matched with `errors.As`; `ErrTimeout`, `ErrOutputTooLarge`, `ErrPageNotFound`. Diagnostics use typst's short format (`main.typ:2:1: error: unknown variable: x`). `CompileError.Error` carries the first error line, which names the template position an operator needs; the diagnostics can quote values the template took from the data, so a service treats them like the data when it logs. |
| T12 | `Escape` puts a backslash before every ASCII punctuation character. typst accepts that escape for each of them, so the set is complete without tracking typst's markup syntax: no character of the input can open a call, a block, a label, a reference, math, raw text, emphasis, a heading, a list, a comment or a shorthand. Line breaks stay text; a blank line is a paragraph break. `Quote` returns a string literal for code mode. Both turn invalid UTF-8 into U+FFFD, which typst would otherwise reject as a whole file. |
| T13 | The work package asked for `MarkdownToTypst`; it is `FromMarkdown`, because `typst.MarkdownToTypst` repeats the package name (NAM-003). It parses CommonMark with the GitHub extensions (tables, strikethrough, task lists, bare links) with goldmark, which has no dependencies, and emits structure only as calls (`#heading(level: n)[...]`, `#list(...)`, `#enum(start: n, ...)`, `#table(...)`, `#raw("...", block: true)`, `#link("...")[...]`, `#emph`, `#strong`, `#strike`, `#quote(block: true)`, `#line`, `#linebreak()`), never as markup syntax. Calls nest without depending on indentation, and every piece of user text passes `Escape` or `Quote`. Links keep only `http`, `https` and `mailto` targets; raw HTML stays visible as text; an image is its alternative text (no file access from user input). The template evaluates the result from the data: `#eval(data.description, mode: "markup")`. |
| T14 | Observability per LIB-012, shaped like `aikido/llm`: `Observer` with `CompileStarted(ctx, *Compile) context.Context` and `CompileFinished(ctx, *Compile, *Outcome)`, started in order and finished in reverse. `Compile` carries `Name` and `Format`, never content. `Outcome.Result` is a closed set usable as a label. `Document.Name` is the template's name from the application's constants. `prometheusadapter`: `<ns>_typst_compiles_total{name,format,result}`, `<ns>_typst_compile_duration_seconds{name,format}`, `<ns>_typst_output_bytes{format}` on the caller's `Registerer` (LIB-011). `oteladapter`: one internal span `typst.compile` with `typst.name`, `typst.format`, `typst.result`, `typst.output_bytes`; a failure sets status error with its result, never the error text (TRC-006). |
| T15 | One module. The root package needs only goldmark; client_golang and the OpenTelemetry API are imported by the adapter packages alone, so module graph pruning keeps them out of a consumer that does not import an adapter (the jobs and aikido layout). |
| T16 | Unit tests never run typst. The test binary is its own fake: started with `compile` or `--version` as its first argument, `TestMain` acts out what `main.typ` asks for (echo the arguments, environment and files; fail with diagnostics; hang; flood stderr; write n bytes). The switch is the argument, not an environment variable, because `Compile` clears the environment. A symlink named `typst-<version>` selects the reported version. The fake leaves through `syscall.Exit`, which skips the race detector's one-second exit hook. The whole unit suite takes about 2 s cold and is replayed from the test cache when unchanged. |
| T17 | The escaping claims are tested twice. Fuzz targets (their seeds run in every `go test`) check `Escape`, `Quote` and `FromMarkdown` against a parser of the exact Typst subset the converters may emit, which rejects any unescaped punctuation, any call outside the emitted set and any string that does not decode to the input. The end-to-end suite evaluates hostile text and Markdown inside the real typst and asserts, in the template, that the resulting content's plain text equals the input. |
| T18 | The end-to-end suite (`e2e` build tag) runs against typst 0.15.1, which `just install-typst` downloads into `sandbox/typst/` and checks against the release's SHA-256. `just test-e2e` skips the suite when its compiled binary, `test/e2e` and the pinned version equal a green run (TST-015). It needs no network itself: the package-download test proves the download is blocked. |
| T19 | Amends T13: `FromMarkdown`'s output always compiles and its work is bounded, because the Markdown comes from remote users and a refused document is a permanent failure for the service. Emitted calls nest at most 8 deep (block quotes, lists, tables, headings, emphasis, links, counted together); deeper structure keeps its text. typst 0.15.1 refuses 17 nested block quotes ("maximum show rule depth exceeded") and the template's own nesting draws on the same budget; 8 passed every combination measured inside a template nested 4 deep, on 0.13.0, 0.14.2 and 0.15.1. A link target over 8000 bytes ("URL is too long" in all three) keeps only its label. Inputs over `MaximumMarkdownSize` (32 KiB) are returned as `Escape` of the input: goldmark's parse is quadratic on nested containers and link brackets (0.4 s worst case at 32 KiB, 24 s at 256 KiB on an Apple M-class core), and the bound also caps the writer's recursion, which overflowed the stack (fatal, not a panic) around 800 KB of `>`. goldmark fills every short table row up to the header's width, so 32 KiB of one-cell rows under a 3000-column header took 3.5 GB; when an upper estimate of the cells (per paragraph: lines times the widest delimiter-like row) exceeds 65536, the input is parsed without the table extension. Output beyond 32 times `MaximumMarkdownSize` (a reference link repeated copies its target) returns `Escape` of the input. |
| T20 | Amends T13: backslash escapes and entities are resolved in one pass over text and link targets, so what one produces is never read again (`\&copy;` stays the text `&copy;`), and the scheme allowlist judges the resolved target. Line endings inside an inline code span become spaces (CommonMark). |
| T21 | Amends T10: when the caller's context ends, `Compile` wraps `ctx.Err()`, never `context.Cause(ctx)`. A cause is the caller's own error: `errgroup.WithContext` cancels the others with the first failure, which would make every cancelled compile match that failure's `*CompileError`. |
| T22 | Amends T3 and T5: a failed removal of the render directory is returned joined with the compile's own error, so a failed compile does not leave the caller's data behind without a trace, and `errors.Is`/`errors.As` still match the compile's error. `Options.TemporaryDirectory` must exist at `New`, like the font and package directories. `Document.Files` paths may not contain NUL, may not equal another path or a reserved file ignoring case, and may not be a directory of another path or of a reserved file; all of that is `ErrInvalidDocument` before anything runs. Case folding is `strings.ToLower`, not the file system's Unicode folding. `Options.Version` is checked against an anchored `major.minor.patch`. |
| T23 | Amends T14: `Outcome.Warnings` carries what typst printed on a successful compile. typst reports a font missing from `FontPaths` as a warning and renders the fallback font with exit code 0, so without it the most likely production defect of a template is invisible. It is on the Outcome, not the return value, so `Compile` keeps its signature; it can quote data, like the diagnostics. Every observer's `CompileFinished` receives the context the last observer returned, so an observer keeps its state under its own context key: `oteladapter` stores its span under a key holding the `*Spans`, so two tracing observers end their own spans. |

## 2. Not in v1, and when to add it

- A concurrency limit. Every compile starts a process that uses all cores. Services render from a govengers/jobs queue, whose per-queue concurrency is the limit; add a semaphore option when a synchronous endpoint renders under load.
- Templates and fonts from an `fs.FS`. Today a service reads its embedded templates into `Document.Source` and `Document.Files`, and writes embedded fonts to a directory at startup for `FontPaths`. Add `fs.FS` options when a second service repeats that code.
- `--creation-timestamp`, PDF standards (`--pdf-standard`), HTML export: add with the first service that needs reproducible bytes, PDF/A or HTML.
- `Options.FailOnWarning`, so a missing font fails the render instead of reaching `Outcome.Warnings`: add when a service wants renders with warnings refused rather than logged.
- A `wideeventadapter`: the service records the compile on its own wide event from the returned error; add it when two services write the same fields.
